Пример результата для дубликатов `description` (у 9 страниц было одинаковое
«Интернет-магазин»):

```
/info/refund/            -> Возврат товара и денежных средств — раздел «Информация» на сайте Релод. …
/info/how-to-delivery/   -> Доставка и оплата — раздел «Информация» на сайте Релод. …
```

Заголовки взяты из соседних отчётов (`Same Title and H1`), а не из
транслитерации адреса.

## Что нельзя подтвердить без установки на живой сайт

Проверялась только та часть, которая не зависит от Битрикса: чтение файлов,
распознавание типов, сопоставление колонок, подбор значений, приоритеты.

Не проверялось вживую и требует прогона на staging:

- сопоставление адреса с элементом или разделом инфоблока
  (`UrlResolver` — зависит от шаблонов `DETAIL_PAGE_URL` конкретного сайта);
- запись в SEO-поля через `Bitrix\Iblock\InheritedProperty\*`;
- правка файлов статических страниц;
- откат изменений;
- миграция структуры БД с версии 1.x;
- реальные HTTP-запросы к сайту (`LivePageInspector`).

Поэтому первый запуск обязательно делать на копии сайта.

## Исправленные дефекты версии 1.x

1. **Сохранение молча не работало.** `PLACE_HINT` был `VARCHAR(255)`, а код
   писал туда 250–280 символов пояснений. MySQL в строгом режиме отклонял
   `UPDATE`, ошибка не показывалась. Все пояснительные поля переведены в `TEXT`.
2. **Английские отчёты не распознавались.** В словаре типов было четыре
   английских варианта из сорока. Теперь имя файла Netpeak разбирается
   структурно, плюс распознавание по сигнатуре колонок.
3. **Title и description исправить было невозможно.** Модуль умел только
   искать подстроку в текстах элементов. Добавлена запись в настоящие
   SEO-поля Битрикса.
4. **Домен и тексты были зашиты в код** под один сайт.
5. **Маска LIKE не экранировалась** при поиске вхождений: символы `%` и `_`
   из адреса работали как подстановочные.
6. **Приоритет не учитывался** — все проблемы были равнозначны.
