# RELOD SEO Fixer 2.0 для 1С-Битрикс

Модуль превращает отчёты Netpeak Spider в конкретные, проверяемые исправления
на сайте под управлением 1С-Битрикс.

Работает с любым количеством сайтов: домен берётся из имени файла отчёта и
сопоставляется с сайтами в настройках Битрикса. Никаких зашитых в код доменов,
названий компаний и текстов.

## Главный принцип

Модуль не применяет изменения сразу после загрузки отчёта.

1. Администратор загружает один или несколько XLSX/CSV-файлов Netpeak.
2. Модуль определяет сайт, тип отчёта и разбирает строки.
3. Модуль **открывает страницы на сайте прямо сейчас** и сверяет отчёт
   с фактическим состоянием.
4. Модуль находит, что именно в Битриксе отвечает за каждый адрес.
5. Модуль показывает: что найдено, где найдено, что сейчас, что предлагается,
   что произойдёт при применении и чем это грозит, если не чинить.
6. Администратор проверяет и подтверждает пункты — поштучно или массово.
7. Только после этого модуль применяет подтверждённое, сохранив старое значение.
8. Любое изменение можно откатить.

## Приоритеты

Наивысший приоритет — дубликаты `title` и `description` (100): из-за них
страницы конкурируют друг с другом в выдаче. Для них есть отдельная страница
«Дубликаты title и description» с массовым подбором уникальных значений.

Далее по убыванию: отсутствующие и пустые мета-теги, слишком короткие и
длинные, H1, доступность страниц, битые ссылки и редиректы, индексация,
внутренний вес, адреса, скорость.

## Что модуль исправляет сам

- `meta title`, `meta description` и заголовок страницы у элементов и разделов
  инфоблоков — через штатный API инфоблоков (вкладка «SEO»);
- те же поля у статических страниц — через `SetPageProperty`/`SetTitle`
  в файле страницы, с резервной копией файла;
- точную замену адреса в текстах, описаниях разделов, свойствах инфоблоков
  и описаниях файлов — для ссылок на редиректы, битых ссылок, `http` → `https`,
  заглавных букв и ошибок в записи адреса.

## Что модуль намеренно не делает автоматически

- не трогает файлы ядра Битрикса;
- не меняет файлы шаблонов, пока это отдельно не разрешено в настройках
  (по умолчанию выключено — модуль только показывает файл, строку и фрагмент);
- не снимает `nofollow` массово;
- не переписывает `canonical`;
- не настраивает 301-редиректы пачками;
- не чинит 5xx и медленный ответ сервера — это серверные задачи.

Для всего перечисленного модуль показывает точное место, причину и готовое
решение, но выполняет его человек.

## Как модуль подбирает тексты

Заголовок страницы берётся по порядку из:

1. живого `H1` страницы (если проверка сайта включена);
2. названия элемента или раздела в Битриксе;
3. заголовков, встреченных в других отчётах по этому же адресу
   (справочник `PageFacts` — благодаря ему осмысленные значения получаются
   даже когда сайт недоступен);
4. сегмента адреса — только как последнее средство.

Текст описания берётся из первого доступного источника:

1. **Настоящий текст страницы**, прочитанный при живой проверке. Модуль
   отбрасывает меню, шапку, подвал, формы и куки-баннеры, собирает абзацы
   контента и набирает описание целыми предложениями. Такой текст естественный
   и уникален сам по себе.
2. **Развёрнутый заголовок самой страницы**, если он содержательнее короткого
   названия. На многих сайтах в `title` вынесено описание раздела — это тоже
   текст сайта, а не выдумка модуля.
3. **Типовая формулировка** для страницы понятного назначения — контакты,
   доставка, оплата, возврат, реквизиты, прайс, акции, корзина, каталог, блог,
   FAQ. Фразы описывают, зачем страница нужна, и не утверждают фактов о её
   содержимом, которые модуль не может проверить.
4. **Название страницы и сайта** — короткий, но точный вариант.

Заголовок собирается по настраиваемому шаблону (раздел «Настройки»):

- `tpl_title` — по умолчанию `{label}{ – section}{ | brand}`
- `tpl_description` — по умолчанию `{label}{ — раздел «section»}{ на сайте brand}. {tail}`

Подстановки: `{label}` — название страницы, `{section}` — родительский раздел,
`{brand}` — название сайта, `{tail}` — дополнение. Блок в фигурных скобках
исчезает целиком, если значение пустое.

### Как модуль следит за качеством текста

- **Не повторяет слова**: не допускает «раздел «Информация» … Актуальная
  информация» или «Реквизиты компании: … реквизиты компании».
- **Не обрывает фразу**: убирает повисшие в конце предлоги, союзы, глаголы
  в неопределённой форме и прилагательные без существительного —
  «Учебники по китайскому купить лучшую методическую» превращается
  в «Учебники по китайскому», а не в «Учебники по».
- **Не подставляет транслит**: латинский слаг из адреса («Delivery», «Info»)
  никогда не попадает в русский текст.
- **Чистит опечатки исходника**: схлопывает подряд идущие предлоги
  («условия продажи товаров в для физических лиц»).
- **Не добивает «водой»**: если материала мало, описание останется коротким,
  а в подсказке будет честно написано почему и что дописать. Одинаковая фраза
  в конце каждого описания снова превратила бы их в почти-дубликаты, поэтому
  хвост-заглушка по умолчанию выключен.
- **Предупреждает об обрезке**: если исходный `title` был перегружен ключевыми
  словами и его пришлось сократить механически, уверенность понижается до 40 %,
  а в подсказке прямо сказано, что фразу нужно перечитать.

## Установка

1. Скопировать папку `relod.seofixer` в `/local/modules/`.
2. В админке открыть список модулей и установить «RELOD SEO Fixer».
3. Открыть «Сервисы → RELOD SEO Fixer».
4. Зайти в «Настройки» и проверить:
   - у каждого сайта заданы домены (иначе отчёт не сопоставится с сайтом);
   - название сайта для подстановки в тексты;
   - доступность сайта — кнопка «Проверить адрес».
5. Первый прогон делать на копии сайта или staging.

### Обновление с версии 1.x

Установить модуль поверх и **обязательно** нажать
«Настройки → Проверить и починить структуру БД». Миграция добавит новые поля и
расширит слишком короткие колонки. Данные не удаляются.

## Рекомендуемый порядок работы

1. Загрузить отчёты Netpeak (можно все сразу), оставив включёнными
   «Подготовить решения» и «Проверять сайт в реальном времени».
2. Открыть «Обзор» — увидеть проблемы по приоритету.
3. Начать с «Дубликаты title и description»: подобрать значения → просмотреть →
   подтвердить → применить.
4. Проверить «Журнал изменений» и сам сайт.
5. Перейти в «Проблемы» и разобрать остальное по убыванию приоритета.
6. Посмотреть «Не выполнено» — там лежат задачи, которые модуль осознанно
   не стал делать, с точной причиной.
7. Повторить обход Netpeak тем же профилем и загрузить новые отчёты:
   исправленное закроется автоматически.

## Безопасность

Перед каждой правкой модуль:

- проверяет, что пункт подтверждён администратором;
- открывает страницу вживую и убеждается, что проблема ещё существует;
- отказывается править страницу, которая сейчас отдаёт ошибку;
- сравнивает текущее значение с ожидаемым и пропускает пункт, если значение
  изменилось после проверки;
- сохраняет старое значение в журнал;
- перечитывает поле после записи и считает правку успешной только если
  значение действительно сохранилось;
- ограничивает количество правок за один запуск.
